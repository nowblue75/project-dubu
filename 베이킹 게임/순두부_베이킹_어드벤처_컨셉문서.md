# 게임 컨셉 문서 (초안 v1)

## 로그라인

> 건강과 기쁨을 함께 채우고 싶었지만 그러지 못했던 스승의 레시피북을 이어받아, 순두부라는 첫 실마리에서 시작해 나만의 배합을 완성해가는 10분 단위 베이킹 어드벤처.

## 장르 / 포지셔닝

- **장르**: 레시피 어드벤처 + 조합(alchemy/combination) 게임
- **참고 장르 계보**:
  - Doodle God류 (조합 기반 발견의 재미, 전 세계 1.9억 명 플레이) — 매칭 인터페이스의 근거
  - Infinite Craft (2024년 화제작, AI 기반 무한 조합) — "발견"이 왜 매력적인지의 근거
  - Potion Craft: Alchemist Simulator (Steam 출시 첫날 판매 1위, 리뷰 93% 긍정 16,000+) — Steam 시장에서 "조합 프로세스의 손맛"이 통한다는 가장 강력한 근거
- **차별점**: 기존 조합 게임들은 조합 로직이 자의적(불+물=증기)인 반면, 이 게임은 실제 베이킹 원리에 기반한 "말이 되는" 조합으로 진짜 지식이 쌓이는 경험을 제공. Potion Craft가 짚힌 약점(핵심 조합 루프는 좋으나 주변 콘텐츠가 반복적으로 느껴짐)을 서사·관계 축으로 보완.

## 핵심 세계관

- 베이킹 지식은 **암묵지(tacit knowledge)** — 손의 감각, 반죽의 탄성, 그날의 습도 판단 등은 데이터로 옮겨지지 않음.
- 세계관 룰: 인류가 모든 베이킹 지식을 하나의 아카이브로 통합하려 시도했으나, 정보가 친밀한 관계의 규모(가족/사제 단위)를 넘어서려는 순간 **스스로 붕괴하거나 왜곡됨**. 원인은 불명 — 인간의 방해가 아니라 세계가 그렇게 작동하는 법칙.
- 결과적으로 지식은 구전, 암기, 혹은 개인 노트로만 전해짐. 대량 인쇄/배포 시도는 실패함.
- 톤: 무겁게 다루지 않음. "그럴듯하다" 정도의 개연성만 확보하는 배경 장치.

## 멘토 캐릭터

- **이름**: 온 (溫) — "따뜻함"의 의미. 스승이 추구했던 건강함+기쁨의 온기를 담은 오리지널 이름. (주의: 「AI닥터」의 '바루다' 등 참고 작품의 캐릭터명을 그대로 사용하지 않음 — 캐릭터성/관계 구조만 참고했을 뿐, 고유명사는 저작권 문제로 별도 창작함)
- **매개체**: 스승의 인격이 깃든 낡은 레시피북. 죽거나 갇힌 것이 아니라, 지식이 살아남을 수 있는 유일한 형태(1:1 관계)로 존재하는 것.
- **캐릭터성 참고**: 웹툰 「AI닥터」의 AI 캐릭터 '바루다' — 항상 곁에서 말을 걸고, 갈구고, 유머를 던지며 성장을 이끄는 관계형 캐릭터. 정적인 "노트"가 아니라 매 조합마다 반응하는 살아있는 존재감.
- **스승의 한(限)**: 빵을 좋아했지만 혈당 문제로 원하는 디저트를 마음껏 먹지 못함. "건강함을 채우면서도 맛있고 예쁘고, 함께 나눌 때 다 같이 기뻐할 수 있는" 디저트를 만들고 싶었으나 끝내 완성하지 못함.
- **관계 축**: 챕터를 가로질러 누적됨. 초반엔 훈수 두는 입장이지만, 유저가 스승의 영역을 넘어서기 시작하면 반응이 달라짐 ("이건... 내가 생각 못했던 거네").

## 핵심 루프: 발견 → 재현 → 극복

1. **발견**: 스승의 오래된 레시피 노트를 하나씩 탐험/복원
2. **재현**: 노트에 적힌 대로 재료를 조합해 스승의 레시피를 성공적으로 만들어냄
3. **극복**: 같은 레시피를 내 방식대로 비틀어(식감 조절, 대체 재료, 스타일 변주) 개선함

이 3단계 구조 덕분에 레시피 하나가 "한 번 조합하고 끝"이 아니라 **미니 스킬트리**가 됨 — 반복감 문제에 대한 핵심 해법.

## 조합 인터페이스

- **뼈대**: 재료 두 개를 끌어다 붙이는 매칭 기반 (Doodle God식 — 빠르고 직관적)
- **손맛 장치**: 조합 시 재료군별로 정해진 단순 제스처 1개 트리거 (드래그 / 클릭 타이밍 / 슬라이더 맞추기 수준. 리듬게임식 박자 판정은 제외 — 개발 리소스 부담 대비 효용 낮다고 판단)
- **제스처 종류는 3~5개로 제한** → 재료가 늘어나도 콘텐츠 양이 폭발하지 않도록 재사용
- **실패 없음, 숙련도만 차등**: 대충 하면 기본 결과물, 잘 해내면 숙련된 결과물. 좌절감 최소화
- "극복" 단계는 이 제스처 숙련도와 연결 — 극복하려면 제스처를 완벽하게 해내야 함

## 진행 구조

- **챕터 단위 = 디저트 종류별** (크럼블 → 타르트 → 갈레트 → 쿠키 등). 접근성과 인지 편의성을 위해 재료군/시대 구분 대신 채택
- **시작점**: 순두부 기반, 섞으면 바로 결과가 확인되는 단순 공정 — 스승이 이미 도달했던 영역을 재현하며 신뢰를 쌓는 구간
- **중후반**: 공정이 정교해지고 이론적으로 새로운 조합이 등장 — 스승도 도달하지 못했던 미지의 영역으로 유저가 앞서나감

## 엔딩 컨셉

- "완전한 창작이란 없다"는 전제 위에서, 스승의 배합에서 조금씩 비껴나가 **나의 입맛, 내 주변 사람들과 함께 즐길 수 있는 나만의 배합**을 완성하는 것
- 스승을 완전히 뛰어넘는 청출어람이 아니라, **스승이 오랫동안 채우지 못했던 자리(건강함+기쁨의 공존)를 나만의 방식으로 채워드리는 것**
- 개발 관점 이점: "완전히 새로운 레시피"를 무한 생성할 필요 없이, 기존 배합에 소소한 변주(비율/대체재/완성도)만으로 엔딩이 성립 → 서사적 온기와 개발 난이도를 동시에 확보

## 세션 설계

- **1회 세션(레시피 1개, 발견~극복)**: 약 10분
- 여러 레시피를 이어서 플레이하면 자연스럽게 30분~1시간 세션으로 확장되는 구조
- 참고: Potion Craft의 포션 1개 제작 시간도 비슷한 구간(10~15분)

## 챕터 1 확정: 순두부 크림치즈

- **선정 이유**: 지영님이 실제로 가장 먼저 개발한 레시피이자, "섞으면 바로 확인되는 단순 공정" 기준에 부합. 오븐 없이 중탕 하나로 완성되는 구조라 초반 튜토리얼에 적합.
- **재료**: 순두부(물기 제거) 150g, 크림치즈 80g, 연유 35g, 옥수수 전분 10g, 레몬즙 2g, 소금 1g
- **조합 트리**:
  1. 순두부(물기 제거) + 소금 → 밑간된 순두부
  2. 밑간된 순두부 + 레몬즙 → 산뜻한 순두부 베이스
  3. 크림치즈 + 연유 → 달콤 크림 베이스
  4. 산뜻한 순두부 베이스 + 달콤 크림 베이스 → 순두부 크림 (1차 결합)
  5. 순두부 크림 + 옥수수전분 → 안정화된 순두부 크림
  6. 안정화된 순두부 크림 + **중탕 제스처(온도 게이지 타이밍)** → 인생 순두부 크림치즈 (완성)
- **제스처 재사용**: 6단계의 중탕 과정은 기존에 설계한 "오븐 굽기" 타이밍 제스처(게이지 적정 구간에서 멈추기)를 온도 게이지로 스킨만 바꿔 그대로 재사용 — 신규 제스처 개발 불필요
- **극복(내 배합) 변주 포인트**: 연유 비율(단맛 강도) / 순두부 물기 제거 정도(질감) / 레몬즙→요거트 대체(산미 뉘앙스) / 소금 비율(짠단맛 밸런스)

## 챕터 간 재료 연결 구조 (신규)

챕터 1의 완성 결과물(순두부 크림치즈)이 다음 챕터(예: 노오븐 순두부 티라미수)의 재료로 재사용되는 구조를 기본 설계 원칙으로 채택. 챕터가 서로 단절되지 않고, 초반에 만든 결과물을 후반에 다시 활용하는 성취감을 제공. 향후 챕터 설계 시 "이전 챕터 결과물을 재료로 흡수할 수 있는가"를 우선 검토 기준으로 삼는다.

## 아직 정하지 않은 것 (다음 논의 대상)

- 챕터 순서와 각 챕터가 스승과의 관계에서 담당하는 감정적 국면 (예: 입문 → 반항/실험 → 화해/통합)
- 첫 챕터(크럼블 편 등)의 구체적 재료·조합 트리 설계
- 아트 스타일, UI 톤
- 스승 캐릭터의 구체적 비주얼/말투
- AI 생성 파이프라인(Veo3/Flow 등)을 게임 내 콘텐츠(멘토 반응, 결과물 비주얼 등)에 활용할지 여부 — 고려는 하되 초기 단계 필수 아님
